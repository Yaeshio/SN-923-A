# UI/UX仕様書 (Draft)

> **改訂メモ (2026-10-28)**: `02_data_model.md` のドメインモデル再定義に合わせて全面改訂。かんばん式の工程管理（`BoardUI`）、製造指示（`OrderUI`）、部品詳細（`DetailUI`）、ユニット管理（`UnitMasterUI`）を廃止し、改訂管理・プリントデータ登録・ジョブ管理・結果記録・歩留まり表示の画面を新設した。
> 暫定扱いの事項は「(暫定)」と明示し、論点は `02_data_model.md` の「9. 未決事項」に集約している。

## 1. アプリケーションフローとエントリーポイント
本アプリケーションのエントリーポイント（ホーム画面・初期表示）は **アセンブリ一覧 (`AssemblyListUI`)** とする。
設計データ（パーツ・改訂）はアセンブリに強く紐づくため、ユーザーはまず対象のアセンブリを選択し、その詳細画面から「パーツのインポート」「改訂登録」へ進む。製造側の操作（プリントデータ登録、ジョブ作成、結果記録、歩留まり確認）は、上部ナビゲーションから直接開く。

```text
アセンブリ一覧 → アセンブリ詳細 ─┬→ インポート
                                  └→ 改訂登録（ダイアログ）
ナビゲーション → プリントデータ登録 → ジョブ作成 → 結果記録 → 歩留まり
```

ナビゲーション項目: アセンブリ / プリントデータ / ジョブ / 歩留まり / マスタ管理

## 3. 画面詳細

### 3.1 アセンブリ一覧 (`AssemblyListUI`)
- **構成**: アセンブリ名のテーブル。作成フォーム（名前入力）、削除ボタン。
- **特徴**:
    - 各行からアセンブリ詳細へ遷移する。
    - 削除時は、配下のパーツ・改訂も削除される（`02_data_model.md` 未決事項 18）旨を確認ダイアログで明示する。

### 3.2 アセンブリ詳細 (`AssemblyDetailUI`)
- **構成**: アセンブリ名ヘッダ、パーツ一覧テーブル、行ごとの改訂履歴の展開表示。
- **パーツ一覧**: モデル名、必要数（`parts_quantity`）、最新改訂、改訂数、操作（改訂を登録・ダウンロード）。
- **改訂履歴**: 改訂番号（「名前 rev.N」）、修正内容メモ、作成日時、ダウンロードボタン（`DownloadPipeline`）。新しい改訂が上に並ぶ。
- **改訂登録ダイアログ** (`PartInstanceRegistrationPipeline`):
    - 修正後データ（STL）のドラッグ＆ドロップまたはファイル選択、修正内容メモの入力（改訂 2 以降は入力を促すが必須ではない）。
    - アップロード中はボタンを無効化し、進行を示す。失敗時は理由をトースト表示する。
- **特徴**:
    - 「インポート」ボタンでインポート画面へ遷移する。
    - 各改訂の3Dプレビューを開ける。

### 3.3 インポート画面 (`ImportUI`。ロジックは `ImportPipeline`)
- **構成**: ドラッグ＆ドロップエリア、ファイル名解析と3Dプレビュー、必要数の入力。
- **特徴**:
    - **アセンブリの指定**: アセンブリ詳細から遷移してくるため、対象アセンブリは「現在選択中のアセンブリ」に固定する（プルダウンは設けない）。画面上にはIDではなく実際の「アセンブリ名」を表示する。
    - 画面全体のドラッグ＆ドロップによるインポート直感操作。
    - Three.js等を用いたSTLモデルの視覚的プレビュー機能で登録前確認。
    - ファイル名（拡張子を除く）からのモデル名自動抽出および自動データ生成。
    - ファイルごとに必要数（既定 1）を入力できる。登録後はマスタ管理画面で編集できる。
    - 登録時に、元データと同一の初期インスタンス（改訂 1）が自動で作られる旨を、完了メッセージに表示する。

### 3.4 プリントデータ登録画面 (`PrintDataUI`。ロジックは `PrintDataRegistrationPipeline`)
- **構成**: モデル選択部（検索付き）、製作モデルリスト（選択済みの一覧）、ファイルのアップロード部、消費レジン量・プリントデータ名の入力。
- **特徴**:
    - **モデル選択**: アセンブリで絞り込める検索付き選択コンポーネント（React Select等）で、パーツインスタンスを選ぶ（複数のアセンブリのパーツを1つのプリントデータに含めてもよい）。既定は各パーツの**最新改訂**とし、候補には「名前 rev.N」と修正内容メモを併記する。同一パーツの別改訂も同時に選べる。
    - **数量**: 選択した行ごとに製作数量を入力する。初期値はパーツの必要数（`parts_quantity`）(暫定。`02_data_model.md` 未決事項 15)。同一インスタンスの重複選択は不可（数量で調整）。
    - **エクスポートデータのアップロード**: スライサーでモデル配置・サポート生成した後にエクスポートしたファイルを、ドラッグ＆ドロップまたはファイル選択で追加する。アップロードが完了するまで登録ボタンを無効にする（ジョブ作成にはエクスポート済みデータが必須のため）。
    - **消費レジン量**: スライス後に判明する値を入力する。単位は未決（`02_data_model.md` 未決事項 8）で、確定までは項目名に単位を併記しない。
    - 登録後は、そのプリントデータからジョブを作成する導線（`JobUI`）を表示する。
    - 登録済みプリントデータの一覧（名前、含まれるモデル、消費レジン量、登録日時）とダウンロードボタンを併設する。

### 3.5 ジョブ管理画面 (`JobUI`)
- **構成**: ジョブ作成フォーム、ジョブ一覧テーブル、ジョブ詳細（結果記録）。
- **ジョブ作成フォーム** (`PrintJobCreationPipeline`):
    - プリントデータ、プリンタ、レジン、フィルム、ジョブ番号を選ぶ・入力する。選択コンポーネントは検索付きとする。
    - **プリンタ**の選択候補には、稼働状態をカラーバッジで表示する（`READY`＝緑、`RUNNING`＝黄、`MAINTENANCE`＝赤）。`MAINTENANCE` は選択不可、`RUNNING` は選択可能だが警告を表示する (暫定。`02_data_model.md` 未決事項 6)。誤操作を防ぐため、稼働状況を選択時点で確認できるようにする。
    - ジョブ番号は手入力を受け付け、重複時はエラー表示する (暫定。未決事項 12)。
- **ジョブ一覧**: ジョブ番号、プリントデータ名、プリンタ、レジン、フィルム、結果の記録状況（未記録／記録済み）、歩留まり。**各行にプリントデータのダウンロードボタン**を配置し、いつでも最終データを取得できる。
- **結果記録** (`JobResultRecordingPipeline`):
    - ジョブ詳細に、プリントデータの製作モデルリストの行（「名前 rev.N」、製作数量）を一覧し、行ごとに成功数・失敗数を入力する。
    - 現場のタブレットで操作しやすいよう、数値入力に大きな ＋/－ ボタンを備える。
    - 成功数＋失敗数が製作数量を超える場合は警告を表示するが、保存は可能とする (暫定。未決事項 7)。
    - 保存済みの結果は再入力で上書きして訂正できる。個体の識別は行わない。

### 3.6 歩留まり画面 (`YieldUI`)
- **構成**: 集計軸の切り替え、絞り込み条件、集計テーブル。
- **特徴**:
    - **集計軸**: ジョブ別／パーツ別／改訂別／プリントデータ別／期間別を切り替える。
    - **絞り込み**: アセンブリ、パーツ、期間。
    - **表示項目**: 成功数、失敗数、製作数量（計画数）、歩留まり。記録がないグループの歩留まりは「未記録」と表示し、0%とは区別する。
    - **改訂別の比較**: 同じパーツの改訂を並べて、設計修正の前後で歩留まりがどう変わったかを比較できる。修正内容メモを併記する。
    - 横断集計（ジョブ別以外）では、結果が未記録のジョブは対象外であることと、その件数を注記する (暫定。`04_logic_api.md` の `YieldQuery`)。

### 3.7 マスタ管理専用UI (`MasterUI`)
- **構成**: アセンブリ、パーツ、プリンタ、レジン、フィルムのマスタデータを個別のタブから呼び出し、テーブル形式で表示する専用管理画面。
- **機能詳細**:
    1. **アセンブリ**: 一覧表示、および作成・削除機能。
    2. **パーツ**: 一覧表示、モデル名・必要数の編集、削除機能。新規追加はファイルが必須のため、インポート画面から行う（このタブには追加ボタンを置かず、インポート画面への導線を置く）。改訂の確認はアセンブリ詳細へ誘導する。
    3. **プリンタ**: 一覧表示、追加機能。整備中などへの「ステータス強制変更機能」（`PrinterStatusPipeline`。※実際のステータス制御は現在のスコープ外）。
    4. **レジン**: 一覧表示、追加、削除機能。
    5. **フィルム**: 一覧表示、追加、削除機能。
- **特徴**:
    - 上記1〜5の各項目を個別のタブから呼び出し、統一されたテーブル形式で一覧表示・操作を行うインタフェースを提供する。
    - ジョブから参照されているプリンタ・レジン・フィルムは削除できず、その理由をメッセージで示す（`02_data_model.md` 未決事項 18）。

## 4. 廃止した画面
次の画面は本改訂で仕様から削除した。実装も順次除去する。

- **製造指示画面 (`OrderUI`)**: 個体（PartItem）の生成とBox確保。→ プリントデータ登録（`PrintDataUI`）とジョブ作成（`JobUI`）に置換。
- **工程管理ボード (`BoardUI`)**: かんばん式のステータス管理、一括操作、重大変更時の理由入力。→ 廃止（後工程のステータス管理は現スコープ外）。
- **部品詳細画面 (`DetailUI`)**: → アセンブリ詳細（`AssemblyDetailUI`）に統合。
- **プロジェクト管理画面 (`ProjectMasterUI`) / ユニット管理画面 (`UnitMasterUI`)**: → アセンブリ一覧（`AssemblyListUI`）に置換。ユニットは廃止。
- **マスタ管理のBOXタブ**: Box管理の廃止に伴い削除。

## 5. 全体的なUX方針
- **レスポンシブと現場端末への最適化**: 工場内のタブレット端末や共有タッチパネルを想定し、タップ領域（ボタン・選択肢）を大きく確保したタッチファーストな設計。
- **確実なフィードバック**: 通信状態やエラーのトースト通知、非同期処理時のスケルトンスクリーンやローディング表示の徹底により、利用者の不安を軽減。ファイルのアップロード中は進行状況を示し、完了までは登録操作を無効にする。
- **破壊的操作の確認**: アセンブリ・パーツ・改訂の削除は、影響範囲（配下の削除、製作モデルリストに転記済みであること）を示す確認ダイアログを挟む。
- **リアルタイム同期**: 他操作の即時反映（Supabase Realtime等）は、かんばん式の同時操作が前提だった旧仕様ほどの必要性がなくなったため、**任意（Phase 2 以降）**とする。同一ジョブの結果が同時に編集された場合は、後から保存した内容で上書きする。
