## 1. システム概要
本システムは、光造形3Dプリントの製造において「**何のデータを、どの設備・材料で、何回印刷し、どれだけ成功したか**」を記録し、歩留まりを把握するためのシステムである。

データは次の2つの文脈で構成する。

- **設計側**: CADから書き出したモデルを、アセンブリ（Assembly）→ パーツ（Part）の2階層で管理する。製作用にデータを修正した場合は、パーツから派生するパーツインスタンス（Part Instance）に改訂番号付きで記録する。
- **製造側**: スライサーでモデル配置・サポート生成した結果をエクスポートしたプリントデータ（Print Data）を単位に、プリンタ・レジン・フィルムを変えながらプリントジョブ（Print Job）を複数回実行し、結果を製作品（Print Result）としてジョブ×モデル単位で集計する。

設計側と製造側は外部キーで結ばず、プリント時点の情報を製造側へ転記して保持する。これにより、設計データの修正・削除が過去のプリント記録に影響しない。

## 2. 背景・目的
- **設計データの迅速な登録**: CADから書き出したSTLファイルをアセンブリ単位で一括登録する。
- **設計修正の記録**: 製作用に行ったデータ修正を、修正後データと修正内容のメモを残して改訂として記録し、修正前のデータも失わない。
- **プリントデータの保存**: プリントに使った最終データ（スライサーのエクスポート）と、含まれるモデル・数量・消費レジン量を記録する。
- **実績の管理**: 同じプリントデータを、プリンタ・レジン・フィルムを変えて複数回印刷した実績を管理する。
- **歩留まりの把握**: パーツ別・改訂別・プリントデータ別・期間別に歩留まりを集計し、設計修正やパラメータ変更の効果を比較する。

## 3. 主要機能範囲
### 3.1 設計管理
- **アセンブリ管理**: アセンブリの作成・一覧・削除。
- **パーツのインポート**: STLファイルをアセンブリへ一括登録する。ファイル名からモデル名を抽出し、アセンブリ1つあたりの必要数（`parts_quantity`）を保持する。登録と同時に、元データと同一の初期インスタンス（改訂 1）を自動作成する。
- **改訂登録（設計修正の記録）**: 製作用に修正したデータをアップロードし、修正内容のメモとともに新しい改訂として追記する。改訂は追記専用で、修正前のデータは上書きしない。
- **ファイル管理**: 外部ストレージを用いた設計データの保存と取得。DBにはストレージ上の相対パスを保持する。

### 3.2 プリントデータ登録
- 製作に使うパーツインスタンス（既定は最新改訂）と製作数量を選び、製作モデルリストを作る。
- スライサーでエクスポートしたデータをアップロードし、消費レジン量とともにプリントデータとして登録する。登録時に、選んだインスタンスの情報（インスタンスID、パーツID、名前）を製作モデルリストへ転記する。

### 3.3 ジョブ管理
- 登録済みのプリントデータに対し、プリンタ・レジン・フィルム・ジョブ番号を指定してプリントジョブを作成する。
- **プリントデータ（エクスポート済みデータ）が登録されていないとジョブは作成できない。**
- 同じプリントデータから、パラメータを変えて複数のジョブを作成できる。

### 3.4 結果記録と歩留まり
- ジョブ完了後に、製作モデルリストの行（パーツインスタンス）ごとに成功数・失敗数を記録する。個体は識別せず、ジョブ×モデル単位の集計に留める。
- 歩留まりを、ジョブ別・パーツ別・改訂別・プリントデータ別・期間別に集計・表示する。定義は `02_data_model.md` の「7. 歩留まりの定義」に従う。

### 3.5 マスタ管理
- アセンブリ、パーツ（モデル名・必要数の編集、削除）、プリンタ、レジン、フィルムを管理する。
- プリンタは稼働状態（`READY` / `RUNNING` / `MAINTENANCE`）を手動で変更できる。状態の自動制御は現スコープ外。

### 3.6 ファイル取得
- パーツインスタンスの修正後データ、およびプリントデータを、署名付きの一時URLでダウンロードできる。

## 4. MVP開発スコープ (Phase 1)
本フェーズでは、以下の3軸の機能実現を最優先とする。ログインは必須とし、設計データは所有者（作成したユーザー）ごとにアクセスを制御する（`02_data_model.md` 8.1）。ロール別の権限管理（設計者／作業者など）は行わない。

### 4.1 設計管理 (Design Management)
- アセンブリ管理、パーツのインポート（初期インスタンスの自動作成を含む）、改訂登録。
- クラウドストレージを用いた3Dデータの一元管理。

### 4.2 製造準備・実行 (Print Production)
- プリントデータ登録（製作モデルリストへの転記を含む）。
- プリントジョブの作成。

### 4.3 結果記録と歩留まり (Results & Yield)
- ジョブ×モデル単位の成功数・失敗数の記録。
- 歩留まりの集計・表示。

## 5. 現スコープ外（旧仕様から削除）
次の項目は本改訂で仕様から削除した。実装・関連文書からも順次除去する。

- **個体（旧 PartItem）単位の追跡**: 同名パーツを複数枚印刷する運用があり、個々の個体の判別が困難なため、ジョブ単位の集計に留める。
- **後工程のステータス管理**: 切削・研磨・検査・出荷などの工程遷移、かんばん式ボード、ステータス変更履歴、理由コード。
- **保管場所（Box）の管理**: 個体とBoxの紐付け、空きBoxの確保、自動解放。
- **製作ステータスの管理**: パーツ登録状態（`PENDING` / `ACTIVE`）を含む。
- **不良理由の分類**: 失敗数のみ記録し、理由は記録しない。

## 6. 将来拡張事項 (Phase 2 以降)
- **ユーザー認証・権限管理**: 設計者、作業者ごとのアクセス制御。
- **ジョブの進行状態**: 開始・完了日時またはステータスの管理。プリンタ状態の自動連動（`02_data_model.md` 未決事項 6）。
- **高度な検索・フィルタリング**: 大規模アセンブリ向けのパーツ検索機能。
- **不良理由の分類**: 失敗数の内訳（造形不良・サポート不良など）の記録。
- **レジン・フィルムの在庫／消費量管理**: 消費レジン量の積算と残量管理。
- **アセンブリの充足率**: 成功数と必要数（`parts_quantity`）の比較による進捗表示。
- **CADデータの改版の取り込み**: 再インポートを新しい改訂として扱う運用。
- **外部システム連携**: ERPや既存BOMシステムとの同期。

## 7. 用語集

| 用語 | 意味 | データ |
| :--- | :--- | :--- |
| アセンブリ | 設計データをまとめる最上位の単位（旧プロジェクト／ユニットに相当） | `assemblies` |
| パーツ | CADから書き出した概念的なモデル。アセンブリ1つあたりの必要数を持つ | `parts` |
| パーツインスタンス | パーツから派生した、製作用に修正したデータ。改訂番号付きの追記専用レコード | `part_instances` |
| 改訂 | パーツインスタンスの版。初期インスタンスが改訂 1 で、修正のたびに +1 する | `part_instances.revision` |
| プリントデータ | スライサーでモデル配置・サポート生成した結果をエクスポートした、プリントに使った最終データ | `print_data` |
| 製作モデルリスト | プリントデータに含まれるモデルと製作数量の一覧。パーツインスタンスからの転記 | `model_list_items` |
| プリントジョブ | プリントデータを、プリンタ・レジン・フィルムを指定して印刷する実行単位 | `print_jobs` |
| 製作品 | プリント後の結果。ジョブ×製作モデルリスト行ごとの成功数・失敗数 | `print_results` |
| 歩留まり | 成功数 ÷ 製作数量 | 集計時に導出 |
| プリンタ | 造形に使う設備。稼働状態を手動で管理 | `printers` |
| レジン | 造形に使う樹脂 | `resins` |
| フィルム | 造形に使うフィルム（要確認: 離型フィルム等の具体） | `films` |
| 転記 | 他テーブルの値を、外部キーを張らずに写し取って保持すること | — |
